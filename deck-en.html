01 — Case study07 / 52
2

Collect the data

Designing a form is designing your data.

  • Anonymous, name optional → more honest answers
  • Multiple choice to count · open text to capture real questions
  • 9 questions, 3–5 minutes → most people finish
Reality: the first version had 2 duplicate questions and 1 question that lost all its options — we fixed the form while it was live.
LessonAlways test with a few people before sending it to everyone.
01 — Case study08 / 52
3

Clean the data

Real data is rarely usable as-is.

  • Google Forms joins multiple answers with commas — but the answers themselves contain commas (“Python, SQL, Power BI…”)
  • → Splitting on commas fails; match against the original option list instead
  • 40+ open-text ideas → merged into 18 questions in 4 groups
for option in OPTIONS: if option in answer: counts[option] += 1
LessonMost of a data project's time is spent right here.

Before we talk about jobs

How do AI, ML, DL and Data Science relate?

Artificial Intelligence
Machines doing tasks that normally need human intelligence.
Machine Learning
A branch of AI: machines learn patterns from data instead of hand-written rules.
Deep Learning
A branch of ML: many-layered neural networks — images, speech, language (LLMs).
Data Science
Getting insight from data with statistics and analysis — using ML/DL when needed.

The overlap: Data Science uses ML as a tool — but not all Data Science work is AI.

02 — The industry18 / 52
Role 1 / 5

Data Engineer

Builds the “pipes” so data arrives correct, complete, and on time.

Learning path
  1. Solid SQL & Python
  2. Databases, data-warehouse modeling
  3. ETL/ELT & orchestration: Airflow, dbt
  4. Big data & cloud: Spark, Kafka, AWS/GCP
Day-to-day work
  • Collect data from many sources: apps, web, sales systems
  • Clean, standardize, load into the warehouse
  • Monitor pipelines: fix late, missing, or wrong data
Use case 1Retail data warehouse
Sales data is scattered across stores, web, and app → unify it in one warehouse, refreshed nightly → the whole company shares one revenue number.
Use case 2Real-time data
A ride-hailing app needs driver locations every second → a streaming pipeline (Kafka) feeds the matching system.
02 — The industry19 / 52
Role 2 / 5

Data Analyst

Turns data into answers to business questions.

Learning path
  1. SQL · Excel / Google Sheets
  2. Descriptive statistics & hypothesis testing
  3. BI: Power BI, Tableau
  4. Data storytelling, business understanding
Day-to-day work
  • Take questions from sales and marketing
  • Query, analyze, find root causes
  • Build dashboards, reports, recommend actions
Use case 1Monthly revenue down 15%
Break it down by region, channel, product → the drop is concentrated in one channel after a delivery-policy change.
Use case 2Checkout A/B test
Compare 2 versions with a statistical test → ship the one that lifts orders. Today's survey case study is Data Analyst work too.
02 — The industry20 / 52
Role 3 / 5

Data Scientist

Builds models that predict and support decisions.

Learning path
  1. Math: probability & statistics, linear algebra
  2. Python: pandas, scikit-learn
  3. Machine Learning & model evaluation
  4. Experiment design, domain knowledge
Day-to-day work
  • Turn business problems into prediction problems
  • Prepare data, engineer features, train & evaluate models
  • Explain results to non-experts
Use case 1Customer churn prediction
A telco / app predicts who is about to quit → customer care sends offers to the right people before they leave.
Use case 2Credit scoring
A bank predicts repayment ability from transaction history → faster loan approval, fewer bad debts.
02 — The industry21 / 52
Role 4 / 5

ML Engineer

Takes models from a notebook into a product that runs for real.

Learning path
  1. Strong programming: Python, data structures, Git
  2. ML & Deep Learning: PyTorch
  3. Backend & APIs: FastAPI, Docker
  4. MLOps: deploy, monitor, retrain
Day-to-day work
  • Package models as fast, stable APIs
  • Automate training & deployment pipelines
  • Monitor: data shifts → accuracy drops → retrain
Use case 1Product recommendations
An e-commerce site shows “you may also like” to millions of users, answering in tens of milliseconds.
Use case 2Fraud detection
Every card transaction is risk-scored by a model right before approval.
02 — The industry22 / 52
Role 5 / 5

AI Engineer

Builds applications on top of AI models — especially LLMs.

Learning path
  1. Solid programming & backend
  2. Deep Learning, NLP, Transformers
  3. LLMs: prompting, RAG, fine-tuning
  4. Agentic systems, evaluation & safety
Day-to-day work
  • Connect LLMs to company data and tools
  • Design RAG and agents; measure answer quality
  • Optimize cost and latency; control hallucinations
Use case 1Internal docs chatbot
Staff ask about processes and policies → a RAG system finds the right document and answers with sources.
Use case 2Customer-service agent
Looks up orders, reschedules, files tickets by calling system APIs — not just replying with text.

Q 18
Most-mentioned wish in the survey

Common mistakes when you're new

“What mistakes do fresh graduates commonly make in this field?”

Security
My most frequent mistake. If you don't see a vulnerability, it's very hard to fix once it's exploited.
Time estimates
Add 20% to your original estimate. Estimate too tight and you burn out — in outsourcing you may even owe contract penalties.
Logging
Log the main data flows when you code — but don't log too much.
Using AI
Using AI is great, but you still have to learn. AI output always needs human review.
